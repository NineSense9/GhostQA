Web 探索测试原型

让浏览器自己走，问题必须走得回来。

给 GhostQA 一个站点和测试规格，它会实际打开浏览器、记录页面状态和转移。发现异常后先重放；复现成功，才记为已确认缺陷。

工作方式

一次探索经过的步骤

  1. BrowserPlaywright 执行动作，留下截图和页面状态。
  2. State model记录已经走过的状态和转移。
  3. Policy按 novelty 和 workflow 进度选下一步。
  4. OracleJS、结构和规格断言生成候选。
  5. Replay走不回来的异常，不算已确认。
  6. Minimize用 ddmin 缩短可复现路径。
  7. Evidence报告、图、trace 和 manifest 留档。

发现异常不等于确认缺陷。

研究记录

v0.3.6 → v0.3.19

  1. v0.3.6 · Structural Memory

    DeepBench 上，structural memory 把重复 branch 尝试压低，同时保住 D6/D12 并找到更多深 workflow 缺陷。Deep-BDR @120：0.667 · development benchmark

  2. v0.3.7 · Frozen Transfer Check

    冻结算法后换到 BuggyShop，C1 只确认 1/10。这轮没有顺手调参，结论直接记为 DeepBench-specific。BuggyShop: 6 states · W5

  3. v0.3.8 · Root Cause

    没有证据表明 fingerprint / semantic-variant explosion 是主要原因；持续的 return loop 已足够解释这次 coverage lock。C0/C1 都记录到 116 次 return attempt，successful return 为 0。

  4. v0.3.9 · Return-Cycle Guard

    exact state 在同一 return phase 再次出现，就放弃这条 return obligation。6 → 22 states · DeepBench lost bugs = 0

  5. v0.3.10 · Fresh Cross-App Transfer

    冻结 candidate 在 BuggyDesk 上再次 escape，并进入 C1 未覆盖状态。成功返回安全用例没有误触发。不是广泛泛化。

  6. v0.3.11 · Preregistered Multi-Target Replication

    Outcome D — inconclusive suite。只有 Wiki 进入 return phase。CRM / Ops 没有。产品默认未改。

  7. v0.3.12 · Nested-Hub Parent Preservation

    外层 sequence 在 nested hub 上不再被 lost_parent 打断。CRM / Ops 是已分析用例。历史回归有确认缺陷丢失。数字来自已发布产物。

  8. v0.3.13 · Suspended Parent Frames

    嵌套分支挂起外层帧并启动真实 child sequence。数字来自已发布产物。候选不晋升。

  9. v0.3.14 · Horizon Handoff

    嵌套分支在 commitment 多于 1 时继续当前 sequence，只在最后一格交给子 sequence。数字来自已发布产物。候选不晋升。

  10. v0.3.15 · Fresh Handoff Validation

    Outcome C。forum 与 billing 完整 transfer，buggy-lab 丢失四个 guard 缺陷，目录对照触发 2 次 handoff。产品默认未改。

  11. v0.3.16 · Early Parent Re-entry

    Outcome B。目录假 handoff 2 → 0。实验记录租约恢复 BUG-L8，仍丢失 BUG-L1、BUG-L9、BUG-L10。历史回归丢失为 0。产品默认未改。

  12. v0.3.17 · Local Action Drain

    Outcome B。run 父页面先点可见按钮，恢复 BUG-L10 和 BUG-L1，BUG-L8 仍在。结果页没有 drain，BUG-L9 仍丢失。目录 handoff 仍是 0。历史回归丢失为 0。产品默认未改。

  13. v0.3.18 · Return-Phase Entry Drain

    Outcome C。结果页 drain 排空 btn_close 和 btn_reopen，BUG-L9 从丢失变为保留。目录 handoff 仍是 0。DeepBench 相对 guard 丢失 D6、D7、D11、D12、D13、D14。产品默认未改。不是 fresh 验证。

  14. v0.3.19 · Finding-Gated Return-Entry Drain

    Outcome A。同一步 finding terminal 才启动 drain，结果页仍保留 BUG-L9。horizon 单独进入返回时不再 drain。DeepBench 相对 guard 的丢失为 0。目录 handoff 仍是 0。产品默认未改。不是 fresh 验证。
